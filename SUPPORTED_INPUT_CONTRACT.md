# Supported input contract — schema 2 / planning schema 3

Production authority is `OptimizationRequest` → `optimize_procurement` → lot MILP → exact FEFO simulation → critic. `run_typed_planning` adds customer export and deterministic M6. Natural language is an optional draft adapter; the engine does not require a parser or LLM.

Stable IDs identify store, product, ingredient, supplier, offer, lot and world. Display names may contain Unicode, duplicate names and spreadsheet metacharacters. Typed identity is `(store_id, ingredient_id)`; raw ambiguous name-only resolution requires explicit IDs/mapping. A name change has no physical meaning. Substitution requires its own effective recipe, terms, lots and conversion evidence. Scoped display mappings use `store_id|entity_id`, falling back to an unscoped name only for presentation.

Inputs must be finite and within the declared numerical domain. Negative demand/cost, Boolean quantities, nonpositive pack size, duplicate IDs/grain, unknown fields/operators and inconsistent weights are rejected. Weighted pools have nonnegative weights summing to one; zero-weight worlds remain in the exact pool and accounting checks, but add zero probability. Partially missing weights are invalid. Unweighted diagnostic worlds cannot certify probability requirements; normalized business-rule reports require explicit weights and otherwise return BLOCKED_INPUT_SEMANTICS. Empty demand/horizon is invalid; an explicit daily grid containing zero demand is supported, with fill=1 and stockout=0. A zero daily reference for purchase-cover rules imposes a zero maximum purchase quantity; coverage days is undefined and is never exported as infinity.

Units: canonical kg, liter and unit; kg/g, L/mL, piece/unit aliases use dimensional conversions. Packaging is ingredient/offer scoped. Cross-dimension conversions require `physical_dimension_bridge=true`, `evidence_id`, `canonical_base_unit` and a consistent factor; no implicit kg=L or piece=kg. Occupancy is separately supplied in liters/base unit. Missing occupancy for an applicable global capacity is BLOCKED_INPUT_SEMANTICS; global capacity is never dropped.

Daily planning uses date-only, explicit snapshot boundary, timezone metadata, lost sales/no backorders and lot-aware FEFO. Shelf-life is **arrival plus calendar-day offset**. `expiry_inclusive` controls usability on expiry day. Duration including receipt day must be normalized explicitly to offset (duration−1 for inclusive convention); do not infer this from an ambiguous source. Receiving peak is measured before expiration disposal and consumption. Ending stock is a separate rule. FEFO sorts expiry, receipt date and stable lot ID. Orders are ex ante; each world shares the same schedule and pack counts.

Supported calendars declare ORDER, RECEIVING or DISPATCH, calendar/business-day lead, order boundary, supplier workdays and dated exceptions. Dispatch has a separate transport offset. Direct typed offers without calendar explicitly use legacy calendar-day offset and a declared order date. The bundle builder enumerates all admissible order dates through the horizon and does not create inbound from purchase history. Receipt after consumption, intraday/time-of-day cutoffs, independent simultaneous calendar scopes and adaptive world-dependent recourse are currently unsupported and must not be represented as accepted before-consumption plans. Record unresolved prerequisites instead.

MOQ is normalized base quantity with integer packs; per-pack prices must be normalized once. Shipment fees are per opportunity or an explicit supplier/store/order/arrival group; a partial-group supplier cash cap is unsupported. Fee thresholds/surcharge formulas beyond an explicit opportunity fee, compartment capacity and shared supplier caps mixing incompatible dimensions require upstream normalization or an unsupported diagnostic. Currency is single VND in the bundle profile path; typed arithmetic may use another single declared currency, with no FX conversion. No quantity aggregation across unlike ingredient units is reported.

Rules supported by the lot model/exact critic: RECEIVING_PEAK, END_OF_DAY_MAX, GLOBAL_RECEIVING_PEAK with occupancy, END_OF_DAY_MIN, PER_KEY_EXPECTED_FILL, PURCHASE_COVER_DAYS with explicit daily reference, MIN_REMAINING_LIFE_AT_RECEIVING. HARD and ADVISORY retain separate acceptance semantics; SOFT is supported for END_OF_DAY_MIN reserves with a positive currency-per-unit penalty. Other soft operators fail validation. Default LEAN/BALANCED/PROTECTED safeguards are engineering policy choices, not fitted business parameters. See `parameter_registry()` and the scenario catalogue. Budget null removes only procurement purchase+delivery cap; finite zero is valid. It does not remove service, capacity, availability or expiry.

Engineering envelope: positive horizon ≤366 days; ≤2000 worlds; ≤200 store/ingredient keys; ≤10000 offers and initial/inbound lots. Demand, inventory, inbound, pack and MOQ quantities are zero where allowed or 1e-6..1e9 canonical units; the lower bound keeps positive terms above absolute accounting/solver precision and the upper bound limits Big-M. Individual price/fee ≤1e12 currency units; each text field ≤16384 characters to bound workbook cells and diagnostic memory. Values outside this domain receive UNSUPPORTED_INPUT, never clamping. Sparse model variable/constraint limits are additionally validated by `SolverLimits` and can be reached before these outer bounds. These are validation/resource bounds, **not a claim that every combination completes within default time**. Verified horizons: typed 1/2/3/7 and explicit cold-start 14; fixed M1 horizons 1..7. Solver uses finite per-solve and total time, node/gap/model limits; increase `limits` explicitly for harder requests.

Feasibility search keeps decomposition as candidate generation and reserves time for a full-pool JOINT_MILP feasibility phase releasing all purchase decisions. Exact PASS may accept a time-limited integer incumbent, with gap/status recorded. Restricted OPTIMAL is not global procurement optimality. No incumbent within resources is SEARCH_LIMIT_REACHED; critic rejection is REJECTED_BY_EXACT_CRITIC. PROVEN_INFEASIBLE requires sound preflight or all declared strategy profiles proven in the full unfixed model. Scope is the supplied worlds/terms/opportunities, never all future customer demand.

Raw preprocessing supports documented CSV/XLSX discovery and reviewable role/column/header mappings, not arbitrary untyped files. Unknown schemas produce mapping review/quarantine; resume with an explicit validated mapping. New fixture filenames/columns are discovered by schema. Existing raw forecast preprocessing is a single-store integration; typed M5 supports multiple stores. Multi-store raw forecasting is not certified. Fixed artifacts are immutable and require temporal eligibility, trained category vocabulary/history and lag availability. New/insufficient-history products require declared forecast overrides plus store calendar, complete per-day product demand/interval rows, evidence/classification, scenario levels/weights and dependence. This cold-start path supports up to366 declared days, preserves its declared intervals and does not run old CQR/residual pools on cold rows. The 14-day fixture demonstrates integration, not forecast accuracy or real supplier facts.

Status authority: FEASIBLE with orders; FEASIBLE with `accepted_zero_purchase=true`; INVALID_INPUT; UNSUPPORTED_INPUT; BLOCKED_INPUT_SEMANTICS; SEARCH_LIMIT_REACHED; REJECTED_BY_EXACT_CRITIC; PROVEN_INFEASIBLE; SOLVER_ERROR. Empty orders alone never means zero-purchase. Technical acceptance, business readiness and execution authorization are separate. Task previews always remain not authorized for execution.

Customer package schema2 uses a single bound view for JSON/CSV/XLSX/Markdown, actual world weights/count and request/config/profile hashes. Perishable ledgers cover all entities; terminal stock is at-risk stock, not certain waste after horizon. CSV strings starting =,+,-,@ use an apostrophe text escape; JSON preserves the original string. Workbook cells are text/date/numeric, never display-name formulas. Consumers must read both JSON authority and text escapes correctly. Package staging is atomic; export failure preserves the accepted technical result, records failure and requires a fresh output directory to rerun.

Legacy cost decomposition field names ending in `_vnd` are compatibility aliases; their numerical values use the bound `cost_currency`. New consumers must use the declared currency rather than infer it from a legacy suffix. M6 monetary evidence binds that same request currency. A historical package without currency remains unspecified unless a reader supplies an explicit binding to its original request; historical files are never rewritten.

Cache/config bindings include content hashes for request, profile assumptions, terms and full scenario pool. Fixed model artifacts and upstream scenario lineage remain separate. No cached result is valid merely because a display name or file path matches.
